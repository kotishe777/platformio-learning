# 05 — Неблокувальний цикл

## Мета прикладу

Мета: незалежно перемикати два LED за часом в одному циклі.
Ціль: ESP32-S3 DevKitC-1 / N16R8; API ESP-IDF 5.5.x, C++, без Arduino і PlatformIO.
`sdkconfig.defaults`: 16 MB Flash, PSRAM вимкнена.

## Схема підключення

GPIO4 → 330 Ω → анод LED1 → катод → GND.
GPIO6 → окремий резистор 330 Ω → анод LED2 → катод → GND.
LED зовнішні, активні HIGH; живлення плати — USB. Перевірте піни за її схемою.
Логічні рівні — 3.3 V; не подавайте 5 V на GPIO.

## Нові функції ESP-IDF та їхні параметри

| Функція або макрос | Призначення, аргументи та результат |
|---|---|
| `gpio_config(&config)` | Застосовує структуру за переданою адресою до GPIO з `pin_bit_mask`; повертає `ESP_OK` або код помилки. |
| `gpio_set_level(gpio, level)` | GPIO виходу та рівень `0` / `1`; повертає `ESP_OK` або код помилки. |
| `esp_timer_get_time()` | Без аргументів; повертає `int64_t` часу в мкс від ініціалізації ESP Timer; не створює callback-таймер. |
| `vTaskDelay(ticks)` | Блокує поточну задачу на задану кількість RTOS ticks; нічого не повертає. |

`constexpr` задає константи часу компіляції; `extern "C"` зберігає ім'я точки входу для стартового коду ESP-IDF. `ESP_ERROR_CHECK(expr)` перевіряє код `esp_err_t`: при помилці друкує діагностику й викликає `abort()`. У `vTaskDelay(1)` аргумент означає один tick, не 1 ms.

`gpio_config_t{}` починається з нульових полів. `pin_bit_mask` вибирає піни:
`1ULL << pin` ставить біт номера GPIO, `|` об'єднує кілька пінів.
`mode` задає input/output; `pull_up_en` і `pull_down_en` керують внутрішніми
підтягуваннями до HIGH/LOW; `intr_type` тут вимикає переривання.
Не присвоєні поля pull лишаються нульовими — підтягування вимкнене.

## Як працює програма — покроково

1. GPIO4 і GPIO6 налаштовуються як output, обидва LED вимикаються.
2. Для кожного LED зберігається час початку його інтервалу.
3. Цикл читає час один раз і окремими `if` перевіряє 200 ms та 700 ms.
4. LED, інтервал якого минув, змінює стан; його відлік починається від поточного часу.
5. Пауза в один tick віддає CPU іншим задачам; очікування 200/700 ms у циклі немає.

`esp_timer_get_time()` повертає час від ініціалізації ESP Timer у мкс, не ms.
`200 * 1000` мкс = 200 ms; `700 * 1000` мкс = 700 ms.
Два окремі `if` порівнюють минулий час для кожного LED. Очікування інтервалу
одного LED не заважає перевіряти інший. Таймерні callbacks і додаткові tasks
не створюються: програма тільки читає системний час.

`app_main()` вже виконується в main task. Наприкінці циклу `vTaskDelay(1)`
віддає CPU на один tick, а не на 200 чи 700 ms. За стандартних 100 Hz tick = 10 ms;
`pdMS_TO_TICKS(1)` дав би 0. Тому назва «неблокувальний» стосується очікування
інтервалів LED; коротка пауза задачі лишається. Перемикання має похибку опитування
і планування. Присвоєння `changed_at_us = now_us` відлічує наступний інтервал від
обробленої події; після довгої паузи пропущені перемикання не надолужуються.

## Відповідність Arduino ↔ ESP-IDF

| Arduino | ESP-IDF |
|---|---|
| `pinMode(pin, OUTPUT)` | `gpio_config()` з output і маскою двох GPIO |
| `digitalWrite(pin, level)` | `gpio_set_level(gpio, level)` |
| `millis()` | `esp_timer_get_time() / 1000`; тут час лишається в мкс |
| `micros()` | `esp_timer_get_time()`; `int64_t`, мікросекунди |

Відповідності наведено за метою; параметри, типи результатів і семантика можуть відрізнятися.

## Запуск

В активованому терміналі ESP-IDF, з каталогу цього проєкту:

```bash
idf.py set-target esp32s3
idf.py build
idf.py -p COMx flash monitor
```

`set-target` — при першій конфігурації; `COMx` замініть портом плати.
Стандартна консоль — USB-to-UART; вихід з monitor: `Ctrl+]`.

## Що студент повинен побачити або виміряти

LED1 змінює стан приблизно кожні 200 ms, LED2 — кожні 700 ms.
Повні цикли: приблизно 400 ms і 1400 ms. Аналізатор покаже два різні ритми.

## Експерименти для самостійної роботи

Змініть `second_interval_us` на `1000 * 1000`: другий LED матиме цикл близько 2 s,
а перший збереже свій ритм.

Джерело: [ESP Timer ESP-IDF 5.5.5](https://docs.espressif.com/projects/esp-idf/en/v5.5.5/esp32s3/api-reference/system/esp_timer.html).
