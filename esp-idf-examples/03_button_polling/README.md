# 03 — Кнопка: опитування (polling)

## Мета прикладу

Мета: читати цифровий вхід з внутрішнім підтягуванням (pull-up).
Ціль: ESP32-S3 DevKitC-1 / N16R8; API ESP-IDF 5.5.x, C++, без Arduino і PlatformIO.
`sdkconfig.defaults`: 16 MB Flash, PSRAM вимкнена.

## Схема підключення

GPIO5 → нормально розімкнена кнопка → GND; внутрішній pull-up увімкнено.
GPIO4 → 330 Ω → анод зовнішнього LED → катод → GND.
Кнопка активна LOW, LED активний HIGH. Плата живиться від USB.
Перевірте піни за схемою плати; не подавайте 5 V на GPIO, логіка — 3.3 V.
Для чотириконтактної кнопки оберіть контакти, які замикаються при натисканні.

## Нові функції ESP-IDF та їхні параметри

| Функція або макрос | Призначення, аргументи та результат |
|---|---|
| `gpio_config(&config)` | Застосовує структуру за переданою адресою до GPIO з `pin_bit_mask`; повертає `ESP_OK` або код помилки. |
| `gpio_set_level(gpio, level)` | GPIO виходу та рівень `0` / `1`; повертає `ESP_OK` або код помилки. |
| `gpio_get_level(gpio)` | Читає налаштований input; аргумент — номер GPIO, результат — рівень `0` або `1`, не код помилки. |
| `vTaskDelay(ticks)` | Блокує поточну задачу на задану кількість RTOS ticks; нічого не повертає. |

`constexpr` задає константи часу компіляції; `extern "C"` зберігає ім'я точки входу для стартового коду ESP-IDF. `ESP_ERROR_CHECK(expr)` перевіряє код `esp_err_t`: при помилці друкує діагностику й викликає `abort()`. `pdMS_TO_TICKS(ms)` переводить ms у ticks відповідно до `CONFIG_FREERTOS_HZ`.

`gpio_config_t{}` починається з нульових полів. `pin_bit_mask` вибирає піни:
`1ULL << pin` ставить біт номера GPIO, `|` об'єднує кілька пінів.
`mode` задає input/output; `pull_up_en` і `pull_down_en` керують внутрішніми
підтягуваннями до HIGH/LOW; `intr_type` тут вимикає переривання.
Не присвоєні поля pull лишаються нульовими — підтягування вимкнене.

## Як працює програма — покроково

1. GPIO4 налаштовується як output, LED вимикається.
2. GPIO5 налаштовується як input з pull-up; це потрібно до першого читання.
3. Цикл зчитує кнопку: LOW означає «натиснуто», HIGH — «відпущено».
4. Результат визначає рівень LED; після паузи близько 20 ms опитування повторюється.
5. Дребезг тут не фільтрується, а натискання між читаннями можуть бути пропущені.

`pin_bit_mask` вибирає вхід, `mode` вмикає читання GPIO, `pull_up_en`
підтягує відпущений вхід до HIGH, `intr_type` вимикає IRQ.
Коли кнопка замикається на GND, `gpio_get_level` повертає `0`:
`pressed = (level == 0)` перетворює електричний LOW на логічне «натиснуто».
Механічний дребезг (bounce) дає короткі повторні зміни рівня під час натискання
та відпускання. Опитування раз на 20 ms не гарантує їх усунення; мерехтіння
може бути непомітним, але підрахунок raw переходів був би ненадійним.
Коротке натискання між читаннями можна пропустити.
`app_main()` — main task; `pdMS_TO_TICKS` переводить ms у ticks планувальника.

## Відповідність Arduino ↔ ESP-IDF

| Arduino | ESP-IDF |
|---|---|
| `pinMode(pin, OUTPUT)` | `gpio_config()` з `GPIO_MODE_OUTPUT` |
| `pinMode(pin, INPUT_PULLUP)` | `gpio_config()` з input і `GPIO_PULLUP_ENABLE` |
| `digitalRead(pin)` | `gpio_get_level(gpio)` |
| `digitalWrite(pin, level)` | `gpio_set_level(gpio, level)` |
| `delay(ms)` | `vTaskDelay(pdMS_TO_TICKS(ms))` |

Відповідності наведено за метою; параметри, типи результатів і семантика можуть відрізнятися.

## Запуск

В активованому терміналі ESP-IDF, з каталогу цього проєкту:

```bash
idf.py set-target esp32s3
idf.py build
idf.py -p COMx flash monitor
```

`set-target` — при першій конфігурації; `COMx` замініть портом плати.
Стандартна консоль — USB-to-UART; вихід з monitor: `Ctrl+]`.

## Що студент повинен побачити або виміряти

Утримуйте кнопку: LED світиться. Відпустіть: LED гасне.
Реакція залежить від моменту наступного опитування і планування задачі.

## Експерименти для самостійної роботи

Змініть `poll_interval_ms` на `200`: затримку реакції буде легше побачити,
а короткі натискання частіше пропускатимуться.

Джерело: [GPIO ESP-IDF 5.5.5](https://docs.espressif.com/projects/esp-idf/en/v5.5.5/esp32s3/api-reference/peripherals/gpio.html).
