# 04 — Усунення дребезгу (debounce)

## Мета прикладу

Мета: одним підтвердженим натисканням перемикати LED один раз.
Це незалежний проєкт; код попереднього прикладу не змінюється.
Ціль: ESP32-S3 DevKitC-1 / N16R8; API ESP-IDF 5.5.x, C++, без Arduino і PlatformIO.
`sdkconfig.defaults`: 16 MB Flash, PSRAM вимкнена.

## Схема підключення

GPIO5 → нормально розімкнена кнопка → GND, внутрішній pull-up.
GPIO4 → 330 Ω → анод зовнішнього LED → катод → GND.
Кнопка активна LOW, LED активний HIGH; живлення плати — USB.
Перевірте піни за схемою плати. GPIO працюють з логікою 3.3 V, не подавайте 5 V.

## Нові функції ESP-IDF та їхні параметри

| Функція або макрос | Призначення, аргументи та результат |
|---|---|
| `gpio_config(&config)` | Застосовує структуру за переданою адресою до GPIO з `pin_bit_mask`; повертає `ESP_OK` або код помилки. |
| `gpio_set_level(gpio, level)` | GPIO виходу та рівень `0` / `1`; повертає `ESP_OK` або код помилки. |
| `gpio_get_level(gpio)` | Читає налаштований input; аргумент — номер GPIO, результат — рівень `0` або `1`, не код помилки. |
| `esp_timer_get_time()` | Без аргументів; повертає `int64_t` часу в мкс від ініціалізації ESP Timer; не створює callback-таймер. |
| `vTaskDelay(ticks)` | Блокує поточну задачу на задану кількість RTOS ticks; нічого не повертає. |

`constexpr` задає константи часу компіляції; `extern "C"` зберігає ім'я точки входу для стартового коду ESP-IDF. `ESP_ERROR_CHECK(expr)` перевіряє код `esp_err_t`: при помилці друкує діагностику й викликає `abort()`. У `vTaskDelay(1)` аргумент означає один tick, не 1 ms.

`gpio_config_t{}` починається з нульових полів. `pin_bit_mask` вибирає піни:
`1ULL << pin` ставить біт номера GPIO, `|` об'єднує кілька пінів.
`mode` задає input/output; `pull_up_en` і `pull_down_en` керують внутрішніми
підтягуваннями до HIGH/LOW; `intr_type` тут вимикає переривання.
Не присвоєні поля pull лишаються нульовими — підтягування вимкнене.

## Як працює програма — покроково

1. Налаштовуються вихід LED і вхід кнопки з pull-up, LED вимикається.
2. Початкове читання задає raw і stable; кнопка, затиснута під час старту, не рахується новим натисканням.
3. Цикл читає raw та час. Кожна помічена зміна raw починає вікно стабільності заново.
4. Після 30 ms без помічених змін raw приймається як stable.
5. Лише підтверджений перехід у «натиснуто» перемикає LED. Відпускання не перемикає його.
6. Пауза в один tick віддає CPU іншим задачам, потім опитування повторюється.

Raw — останній зчитаний рівень; debounced — стан, прийнятий після 30 ms
без помічених змін. Кожна raw зміна оновлює `changed_at_us`; лише після
`now_us - changed_at_us >= debounce_us` оновлюється `stable_pressed`.
Перехід debounced у LOW перемикає LED; утримання та відпускання не перемикають.
Обидва початкові стани беруться з входу: кнопку, затиснуту під час старту,
потрібно відпустити і натиснути знову.

`esp_timer_get_time()` читає час у мікросекундах від ініціалізації ESP Timer;
`30 * 1000` мкс = 30 ms. Читання часу не створює callback-таймер.
`app_main()` вже працює в main task. `vTaskDelay(1)` — пауза на один tick,
за стандартних 100 Hz tick дорівнює 10 ms. `pdMS_TO_TICKS(1)` за цієї частоти
дав би 0. Підтвердження можливе лише під час наступного опитування; короткі
імпульси між читаннями не спостерігаються. Це навчальний програмний фільтр.

## Відповідність Arduino ↔ ESP-IDF

| Arduino | ESP-IDF |
|---|---|
| `pinMode(pin, INPUT_PULLUP)` | `gpio_config()` з input і pull-up |
| `digitalRead(pin)` | `gpio_get_level(gpio)` |
| `digitalWrite(pin, level)` | `gpio_set_level(gpio, level)` |
| `micros()` | `esp_timer_get_time()`; повертає `int64_t` у мкс |
| `delay(ms)` | `vTaskDelay(pdMS_TO_TICKS(ms))`; тут пауза `vTaskDelay(1)` tick |

Відповідності наведено за метою; параметри, типи результатів і семантика можуть відрізнятися.

## Запуск

В активованому терміналі ESP-IDF, з каталогу цього проєкту:

```bash
idf.py set-target esp32s3
idf.py build
idf.py -p COMx flash monitor
```

`set-target` — при першій конфігурації; `COMx` замініть портом плати.
Стандартна консоль — USB-to-UART; вихід з monitor: `Ctrl+]`.

## Що студент повинен побачити або виміряти

Натисніть і утримуйте: LED змінить стан один раз. Відпустіть і натисніть знову:
LED змінить стан ще раз. Дуже короткі натискання фільтруються.

## Експерименти для самостійної роботи

Змініть `debounce_us` на `200 * 1000`: реакція стане повільнішою,
натискання коротше 200 ms не підтверджуватиметься.

Джерело: [ESP Timer ESP-IDF 5.5.5](https://docs.espressif.com/projects/esp-idf/en/v5.5.5/esp32s3/api-reference/system/esp_timer.html).
